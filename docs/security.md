# 数据与安全边界

- 结构验证调用 DSH 官方 catalog，校验日志是否可解码、迁移与恢复。能够构造合法日志的人仍可伪造历史；结构通过不是来源证明。
- 文件 SHA-256 只有与独立可信渠道提供的指纹比较时，才能证明与该参考文件一致。插件不提供作者身份认证或数字签名。
- ZIP 在内存中解析，不把条目名称直接作为写入路径。拒绝目录穿越、绝对路径、符号链接、重复条目、加密/分卷归档、CRC 不一致与超限数据。
- 导入为新会话 ID；不会覆盖同名会话，不安装归档中的代码。历史权限、预设、系统提示词会保留，继续执行使用目标 DSH 的运行规则。
- 图片/文件通过 DSH 附件接口恢复，不写入任意项目路径。归档中的项目文件只有被日志作为附件引用时才会进入附件存储。
- 撤销仅处理拥有导入记录、未打开且未改动的会话，并保留隔离副本；附件可能被多个会话引用，因此永不删除共享附件。
- 官方持久化 API 没有删除或多会话事务。本插件的失败恢复需要默认 JSONL 后端的诊断定位方法；该耦合集中在 `storage-adapter.js`，布局变化时在写入前拒绝。
- 进程崩溃不等于事务回滚。`pending` / `recovery-required` 记录需要检查。恢复时停止使用同一存储的 DSH 进程，并避免覆盖新数据。
- 接口通过官方 `connection.fetch` 注册，沿用 DSH 登录认证和 Host / Origin 信任检查。只在信任导入来源和目标工作区的情况下导入；日志可能含提示词、源码、绝对路径与其他敏感数据。
